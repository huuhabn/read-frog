# Internationalization (i18n) Rules

Workmate AI uses a typed runtime-switchable i18n facade built on top of **`i18next`** and **WXT i18n**, with translation resources stored in YAML files under `src/locales/`.

All AI coding agents creating or editing UI components must strictly follow these rules.

---

## 1. Resource Architecture (`src/locales/*.yml`)

Translations are stored in per-locale YAML dictionaries in `src/locales/`:
- `en.yml` (English - source of truth)
- `vi.yml` (Vietnamese)
- `zh-CN.yml`, `zh-TW.yml`, `ja.yml`, `ko.yml`, `es.yml`, `ru.yml`, `tr.yml`, `az.yml`

Keys are flat or dot-separated paths (e.g. `sidepanel.tabs.webChat`, `common.cancel`, `providers.model`).

---

## 2. Mandatory Rules for AI Agents

### Rule 1: Zero Hardcoded UI Text
- **Never** hardcode user-facing strings directly in JSX (e.g. button labels, placeholders, tooltips, dialog titles, error toasts).
- Always use the typed `i18n.t` facade:
  ```tsx
  import { i18n } from "@/utils/i18n"

  export function ActionToolbar() {
    return (
      <button type="button" aria-label={i18n.t("common.save")}>
        {i18n.t("common.save")}
      </button>
    )
  }
  ```

### Rule 2: Synchronize Translation Files
- When adding a new key or modifying an existing key in `src/locales/en.yml`, **you MUST at minimum update `src/locales/vi.yml`** with accurate translations.
- Keep keys identical across all updated locale files. Do not delete existing translation keys used across the app without checking all call sites.

### Rule 3: Dynamic Substitutions & Prompt Templates
- For string interpolation, use positional placeholders (`$1`, `$2`, etc.) in YAML:
  ```yaml
  itemCount: "Showing $1 of $2 items"
  ```
  And pass substitutions as a tuple:
  ```tsx
  i18n.t("itemCount", [currentCount, totalCount])
  ```
- **Note on Prompt Templates**: LLM prompt templates using double braces (e.g. `{{sourceText}}`, `{{targetLang}}`) are prompt tokens, NOT i18n substitutions. Do not convert double-brace prompt variables to `$1` placeholders.

### Rule 4: Live Language Switching with `<LocaleBoundary>`
- When building standalone React trees (such as in options, sidepanel, or content dialogs), wrap components inside `<LocaleBoundary>` if dynamic re-rendering on language switch is required.
